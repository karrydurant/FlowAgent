# 项目中可以就只使用 HTTP 来引入工具

原生 MCP 的流程：

原生 MCP Server 在连接建立后，必须响应 `tools/list` 请求，返回所有工具的清单：工具名、描述、入参 JSON Schema。

这是 MCP 协议规定的，LLM 靠这个清单知道能调用哪些工具。

在 HTTP 声明工具这个模式里：

tools/list 不再由后端代码提供，而是 "MCP 网关自动生成"，你在页面表单里填：工具名、描述、JSON Schema → 平台保存这份配置。

当 LLM / 客户端发起 MCP 的`tools/list`查询时：
 
网关读取你网页上填写的表单配置，直接拼装出标准`tools/list`的返回 JSON，返回给 LLM。
你的 HTTP 后端完全不用实现`tools/list`，甚至不知道 MCP 存在。

# 使用 HTTP 声明引入工具的注意事项

### 网络层面

1.`localhost / 127.0.0.1 不能直接填！`发起 HTTP 请求的是平台云端网关，不是你的电脑。`127.0.0.1`对网关来说，指向网关自身，访问不到你本机服务。

本地开发：必须内网穿透（ngrok/frp）拿到公网 HTTPS 地址，填入 URL 框；

一旦关闭电脑 / 关闭穿透进程 → 工具直接不可用。

2.防火墙、白名单限制

你的 API 服务器要放行平台网关的出口 IP。如果后端限制访问 IP，网关请求会被拦截报错。

3.超时问题

网关一般有固定超时（通常 10 秒左右，截图下方提示也写了地址不可达约 10s 报错）。
 
如果你的接口计算很慢，超过超时时间，直接失败，拿不到结果。不适合长时间运行的任务。

4.HTTPS 优先
   
绝大多数 MCP 平台网关不支持纯 HTTP 地址，尽量用`https://`。

### GET/POST 与占位符规则

GET 模式

占位符`{param}`可以写在 URL 路径或者 query 参数里：`https://api.xxx/weather?city={city}`
有 URL 长度上限，不能传递超长文本；参数会暴露在日志、请求链接中，禁止传密码、密钥等敏感信息。

POST 模式

URL 里面的 `{参数名} 占位符不会被替换！所有参数全部放进请求 Body（JSON）。
适合长文本、复杂嵌套参数、提交类操作。
